# What is in this zip

Everything needed to run UMS Mart — the Django API, the customer web storefront,
the admin dashboard, and the Flutter Android customer app — plus a prebuilt copy
of the app so you can see it running without installing Flutter.

| Folder | What it is |
| --- | --- |
| `backend/` | Django REST API. `media/` holds the seeded product, category and banner artwork. |
| `frontend/customer-web/` | React storefront (port 5173). |
| `frontend/admin-dashboard/` | React admin panel (port 5174). |
| `mobile/ums_mart_customer/` | Flutter customer app — source, `android/` project, and `serve_web.py`. |
| `mobile/ums_mart_customer/build/web/` | Prebuilt release bundle of that app (same-origin proxy ready). |
| `screenshots/live_app/` | Screenshots from the live run: home, login, OTP, profile, orders, order detail. |
| `docs/`, `deployment/` | Design notes and deployment config. |
| `RUN_CHECKLIST.md`, `TABLE_CREATION_GUIDE.md`, `backend.env` | This session's setup notes and the env file. |
| `README.md`, `RUN.md`, `RUN_LOCAL.md`, `SETUP_GUIDE.md` | The project's own setup documentation. |

## Not in the zip (on purpose)

These are regenerated by one command each, and including them would add ~180 MB:

- `frontend/*/node_modules/` → `npm install`
- `mobile/ums_mart_customer/.dart_tool/` → `flutter pub get`
- `__pycache__/`, `*.pyc`, `venv/`

The `frontend/*/dist/` production builds **are** included.

## Running it

```powershell
# 1. Database (see TABLE_CREATION_GUIDE.md for the full sequence)
#    DB: ums_mart_databaseadmin  user: ums_mart_useradminums  pass: 1234

# 2. API
cd backend
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py seed_data --flush
.\venv\Scripts\python.exe manage.py create_admin --username admin --email admin@example.com --password "UMSMart@Admin2026"
.\venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000

# 3. Customer web        (new terminal)
cd frontend\customer-web
npm install
npm run dev            # http://localhost:5173

# 4. Admin dashboard     (new terminal)
cd frontend\admin-dashboard
npm install
npm run dev            # http://localhost:5174
```

### The Flutter app — no toolchain needed

The web bundle in `mobile/ums_mart_customer/build/web/` is already built against
the live API. Serve it with the proxy that ships alongside it:

```powershell
cd mobile\ums_mart_customer
.\venv\Scripts\python.exe serve_web.py     # or: python serve_web.py
```

Then open **http://localhost:8099**. `serve_web.py` forwards `/api` and `/media`
to `127.0.0.1:8000`, which keeps the app same-origin so the HttpOnly session
cookie behaves exactly as it does on a handset.

Sign in with an OTP mobile from the seed data — `+919876500001` … `+919876500004`.
`AUTH_DEV_MODE=True` in `backend/.env` returns the code in the response, and the
login screen shows it on screen as a "Dev OTP" chip.

### Building for a real Android phone

```powershell
cd mobile\ums_mart_customer
flutter pub get
flutter run                                                       # emulator, uses 10.0.2.2
flutter build apk --release --dart-define=API_BASE=http://192.168.1.38:8000   # physical handset
```

Use your PC's LAN IP (`ipconfig`) for a handset, and make sure Windows Firewall
allows inbound 8000. A release build with no `API_BASE` shows a screen naming the
exact command instead of failing silently.

## About the product artwork

The seeded product and category images are generated gradient tiles carrying the
product's initials — `AS` for Aashirvaad, `IG` for India Gate, `BC` for Biscuits
& Cookies. That is what `seed_data` writes, so those tiles are the real files, not
a broken-image fallback. Drop real photographs into `backend/media/catalog/products/`
using the same filenames and they appear in the web storefront and the app with no
code change.
